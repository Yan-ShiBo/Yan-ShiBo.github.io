# 维护记录

本文集中记录当前实现偏差、后续修复队列以及值得保留的事故经验。它不是测试说明、运维手册、版本流水账或愿望清单；执行命令分别见[测试规范](testing.md)和[运维指南](operations.md)，系统合同见[架构文档](architecture.md)。

## 1. 状态规则

| 状态 | 含义 |
| --- | --- |
| 待决策 | 事实已确认，但产品期望或修复边界尚未确认 |
| 待修复 | 期望明确，可以进入单独实现任务 |
| 已接受 | 当前行为是有意例外，文档已如实说明 |
| 已解决 | 代码或文档已修复，并有回归检查 |

任何条目只有在代码、文档和验证证据同步后才能标为“已解决”。测试未覆盖的行为必须注明人工检查边界。

## 2. 当前维护队列

### M-001 Manifest 图标尺寸元数据不一致

- **状态**：待修复。
- **事实**：`assets/icons/site.ico` 实际包含 16、32、48、256 像素图层，`manifest.webmanifest` 的 `sizes` 声明与实物不一致。
- **风险**：安装入口可能根据错误元数据选择图标；当前验证器只检查图标路径存在，不校验 ICO 内部尺寸。
- **修复边界**：单独核对 manifest 声明，并为尺寸元数据增加自动或人工回归检查。

### M-002 Manifest 默认语言偏向中文

- **状态**：待决策。
- **事实**：所有页面共用一个 manifest，`start_url` 为 `/`，`lang` 为 `zh-CN`。
- **风险**：用户从英文页安装后仍进入中文根页。
- **修复边界**：在“继续共用一个 manifest”和“按语言拆分 manifest”之间做产品选择后再修改。

### M-003 档案页双语结构不完全对称

- **状态**：已接受，等待未来内容任务重新评估。
- **事实**：中文档案使用独立 `#gap-year` 阶段，英文把相同经历放在研究生阶段；两种语言的项目卡片数量也不同。中文页另有两处内联 `style`。
- **风险**：不能用逐节点对比判断双语一致；“禁止任何内联样式”也不是当前已满足的合同。
- **回归边界**：维护语义、链接和证明材料一致性，同时把结构差异当作显式例外。

### M-004 404 倒计时仍是内联脚本

- **状态**：已接受，待未来交互整理。
- **事实**：中英文 404 各自用内联脚本显示倒计时，并在 5 秒后跳转到语言对应入口。
- **风险**：共享交互集中于 `site.js` 的原则存在例外；两份脚本可能漂移。
- **回归边界**：当前先验证 `noindex`、语言对应跳转和 SEO 例外；迁移到共享脚本应作为独立任务。

### M-005 统计有效值校验宽松

- **状态**：待决策。
- **事实**：`validCounter()` 仅排除空值、`--`、`null`、`undefined`、`NaN`、`Loading` 等占位；`0`、负数或其他字符串仍可能被接受。
- **风险**：第三方返回异常文本时，页面可能把它当作有效计数展示。
- **修复边界**：先确认计数是否必须为非负整数，再补实现和异常值测试。

### M-006 英文项目页存在无用途 preconnect

- **状态**：待修复。
- **事实**：`en/projects.html` 保留 `cdn.jsdelivr.net` preconnect，但该页不加载统计脚本或对应 CDN 资源。
- **风险**：产生无意义的网络提示，也让“第三方连接仅存在于统计页”的说明失真。
- **修复边界**：删除前核对页面实际依赖，并增加统计依赖范围扫描。

### M-007 CSS 媒体查询分散

- **状态**：已接受，等待样式重构任务。
- **事实**：1068/1069、833、640、419 等断点分布于样式表多个位置，顺序并非严格从大到小。
- **风险**：后续规则容易被文件尾的同断点覆盖；仅阅读某一段不能得到完整级联。
- **回归边界**：文档记录真实断点，修改响应式规则时检查全部同断点块；不要在文档中假称已经集中。

### M-008 JSON-LD 语言字段覆盖不一致

- **状态**：待决策。
- **事实**：当前只有中英文档案页的 JSON-LD 显式包含 `inLanguage`，其他十个可索引页面没有。
- **风险**：如果未来把 `inLanguage` 定为全站合同，现有页面和验证器都需要同步升级。
- **修复边界**：先确定字段是否必需；当前验证器只在字段存在时校验值。

### M-009 移动抽屉缺少跨断点状态清理

- **状态**：待修复。
- **事实**：`site.js` 在打开与关闭事件中管理 `body.menu-open`、背景 `inert`、遮罩和滚动锁，但没有监听 resize 或媒体查询变化。
- **风险**：在 `<= 833px` 打开抽屉后直接拉宽到 `>= 834px`，桌面导航虽然显示，移动状态仍可能残留。
- **修复边界**：复用现有关闭逻辑，在跨入桌面断点时完整清理状态，并补 833/834px 跨越测试。

## 3. 已解决的典型问题

### H-001 品牌标识事实漂移

- **现象**：部分旧文档把品牌标识描述为 Font Awesome terminal，实际代码已使用 PNG 背景图。
- **根因**：视觉实现更新后，多份重复文档没有同步。
- **解决**：设计与架构只保留 PNG 合同，删除重复术语文档。
- **防复发**：以 CSS 和实际资源为事实源；品牌合同只在[设计规范](design.md)展开。

### H-002 404 被误当作普通 SEO 页面

- **现象**：旧说明一度把 canonical、hreflang 和结构化数据描述成“每页必需”，同时又把 404 `noindex` 误列为未完成债务。
- **根因**：没有把 12 个可索引页面与 2 个错误页面分成两套合同。
- **解决**：404 当前是 `noindex`、无 canonical/hreflang/JSON-LD 且不进 sitemap。验证器自动检查 `noindex`、canonical、hreflang 和 sitemap 排除；“不含 JSON-LD”目前仍需人工检查。
- **防复发**：测试矩阵始终分开描述普通页面和 404。

### H-003 统计范围被写成全站

- **现象**：旧文档把本地累计访问描述成覆盖全部页面。
- **根因**：忽略了 `stats.js` 实际只在中英文首页与统计页加载。
- **解决**：架构与设计明确四页范围，验证器核对脚本加载清单和 DOM。
- **防复发**：新增统计页面时同步更新页面清单、脚本、测试和文档。

### H-004 Sitemap 日期语义被误判

- **现象**：旧运维说明把多个 URL 的相同 `lastmod` 日期视为错误。
- **根因**：混淆了内容历史日期与生成器读取的本地 HTML mtime。
- **解决**：合同改为“每条由对应 HTML mtime 生成，允许同日”。
- **防复发**：验证日期格式和页面集合，不凭日期是否相同判断正确性。

### H-005 双语证明图同步债务过期

- **现象**：部分旧文档仍把英文证明图缺失列为当前债务。
- **根因**：修复完成后，债务段落没有转为历史记录。
- **解决**：当前中英文证明图库存已同步，过期债务从当前架构移除。
- **防复发**：资源变更时按中英文路径和顺序做成对检查；完成项迁入本节，不继续占用维护队列。

## 4. 维护工作流

1. 先从当前代码和页面复现事实，不以旧文档作为结论。
2. 明确问题属于产品选择、代码缺陷、文档漂移还是已接受例外。
3. 需要用户选择或会修改个人内容时，实施前获得明确确认。
4. 每次只处理一个可验证边界，同步代码、文档和测试。
5. 按[测试规范](testing.md)运行自动与人工检查。
6. 完成后把维护队列条目移入“已解决的典型问题”，保留根因和防复发规则，删除过程流水账。

## 5. 新条目模板

```markdown
### M-NNN 简短标题

- **状态**：待决策 / 待修复 / 已接受。
- **事实**：用文件、选择器、状态或可重复现象描述当前行为。
- **风险**：说明会影响谁以及怎样失败。
- **修复边界**：列出需要同步的代码、文档和验证，不预写未经确认的方案。
```

## 6. 文档治理

- 当前合同写入架构、设计、测试或运维的唯一事实源，不在本文复制正文。
- 本文只保留仍需行动的偏差和具有复用价值的根因。
- Git 提交历史承担版本追踪；本文不维护日期式 changelog。
- 已失效、无防回归价值的过程记录直接删除，不另建 archive。
- 任何公开材料都需要通过人工隐私审查；自动验证不能替代内容授权。
