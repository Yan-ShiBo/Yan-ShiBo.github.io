# 维护记录

本文集中记录当前实现偏差、后续修复队列以及值得保留的事故经验。它不是测试说明、运维手册、版本流水账或愿望清单；执行命令分别见[测试规范](testing.md)和[运维指南](operations.md)，系统合同见[架构文档](architecture.md)。

## 1. 状态规则

| 状态 | 含义 |
| --- | --- |
| 待决策 | 事实已确认，但产品期望或修复边界尚未确认 |
| 待修复 | 期望明确，可以进入单独实现任务 |
| 已接受 | 当前行为是有意例外，文档已如实说明 |
| 已解决 | 代码或文档已修复，并有回归检查 |

任何条目只有在代码、文档和验证证据同步后才能标为“已解决”。测试未覆盖的行为必须注明人工检查边界。

## 2. 当前维护队列

### M-003 档案页双语结构不完全对称

- **状态**：已接受，等待未来内容任务重新评估。
- **事实**：中文档案使用独立 `#gap-year` 阶段，英文把相同经历放在研究生阶段；两种语言的项目卡片数量也不同。中文页另有两处内联 `style`。
- **风险**：不能用逐节点对比判断双语一致；“禁止任何内联样式”也不是当前已满足的合同。
- **回归边界**：维护语义、链接和证明材料一致性，同时把结构差异当作显式例外。

### M-004 404 倒计时仍是内联脚本

- **状态**：已接受，待未来交互整理。
- **事实**：中英文 404 各自用内联脚本显示倒计时，并在 5 秒后跳转到语言对应入口。
- **风险**：共享交互集中于 `site.js` 的原则存在例外；两份脚本可能漂移。
- **回归边界**：当前先验证 `noindex`、语言对应跳转和 SEO 例外；迁移到共享脚本应作为独立任务。

### M-007 CSS 媒体查询分散

- **状态**：已接受，等待样式重构任务。
- **事实**：1068/1069、833、640、419 等断点分布于样式表多个位置，顺序并非严格从大到小。
- **风险**：后续规则容易被文件尾的同断点覆盖；仅阅读某一段不能得到完整级联。
- **回归边界**：文档记录真实断点，修改响应式规则时检查全部同断点块；不要在文档中假称已经集中。

## 3. 已解决的典型问题

### H-001 品牌标识事实漂移

- **现象**：部分旧文档把品牌标识描述为 Font Awesome terminal，实际代码已使用 PNG 背景图。
- **根因**：视觉实现更新后，多份重复文档没有同步。
- **解决**：设计与架构只保留 PNG 合同，删除重复术语文档。
- **防复发**：以 CSS 和实际资源为事实源；品牌合同只在[设计规范](design.md)展开。

### H-002 404 被误当作普通 SEO 页面

- **现象**：旧说明一度把 canonical、hreflang 和结构化数据描述成“每页必需”，同时又把 404 `noindex` 误列为未完成债务。
- **根因**：没有把 12 个可索引页面与 2 个错误页面分成两套合同。
- **解决**：404 当前是 `noindex`、无 canonical/hreflang/JSON-LD 且不进 sitemap。验证器自动检查 `noindex`、canonical、hreflang、活动 JSON-LD 和 sitemap 排除。
- **防复发**：测试矩阵始终分开描述普通页面和 404。

### H-003 统计范围被写成全站

- **现象**：旧文档把本地累计访问描述成覆盖全部页面。
- **根因**：忽略了 `stats.js` 实际只在中英文首页与统计页加载。
- **解决**：架构与设计明确四页范围，验证器核对脚本加载清单和 DOM。
- **防复发**：新增统计页面时同步更新页面清单、脚本、测试和文档。

### H-004 Sitemap 日期语义被误判

- **现象**：旧运维说明把多个 URL 的相同 `lastmod` 日期视为错误。
- **根因**：混淆了内容历史日期与生成器读取的本地 HTML mtime。
- **解决**：合同改为“每条由对应 HTML mtime 生成，允许同日”。
- **防复发**：验证日期格式和页面集合，不凭日期是否相同判断正确性。

### H-005 双语证明图同步债务过期

- **现象**：部分旧文档仍把英文证明图缺失列为当前债务。
- **根因**：修复完成后，债务段落没有转为历史记录。
- **解决**：当前中英文证明图库存已同步，过期债务从当前架构移除。
- **防复发**：资源变更时按中英文路径和顺序做成对检查；完成项迁入本节，不继续占用维护队列。

### H-006 移动抽屉跨断点状态残留

- **现象**：在移动断点打开抽屉后切入桌面断点，`menu-open`、背景 `inert`、遮罩、滚动锁和抽屉焦点继续残留。
- **根因**：`site.js` 只处理点击、导航和 Escape 关闭，没有监听 834px 桌面媒体查询变化。
- **解决**：绑定 `(min-width: 834px)` 变化监听，复用关闭逻辑但不聚焦已隐藏的菜单按钮；抽屉内焦点转移到当前桌面导航项，没有当前项时使用首个桌面导航链接，并阻止已关闭抽屉的待执行动画帧重新夺取焦点。
- **防复发**：验证器将 834px 查询、`event.matches`、监听器与处理器内关闭路径作为同一结构合同，变异测试覆盖可能的误通过实现；浏览器验收同时核对 833/834px 的类名、`inert`、遮罩、滚动和焦点。

### H-007 Manifest 图标尺寸元数据漂移

- **现象**：`site.ico` 实际包含 16、32、48、256 像素图层，manifest 却漏报三层并虚报 64、128 像素。
- **根因**：图标资源替换后只同步了路径，没有同步尺寸元数据，也没有实物解析验证。
- **解决**：manifest `sizes` 改为 `16x16 32x32 48x48 256x256`；验证器解析 ICO 目录并精确比较声明集合，畸形或截断文件会安全报错。
- **防复发**：图标替换时同时同步两份 manifest，并运行尺寸不匹配与 ICO 截断回归用例，不再把“路径存在”当成元数据正确。

### H-008 非统计页遗留统计服务连接提示

- **现象**：英文项目页不加载 `stats.js` 或第三方计数资源，却保留了 jsDelivr preconnect。
- **根因**：页面从统计模板派生后删除了脚本，但没有同步删除连接提示，也缺少依赖范围验证。
- **解决**：删除 `en/projects.html` 的无用途 preconnect；验证器将 Busuanzi、jsDelivr、Vercount 的统计专用 preconnect 限制在四个统计页面。
- **防复发**：页面增删统计能力时同时核对脚本、计数 DOM 与服务连接提示，非统计页回归用例会阻止依赖范围再次扩大。

### H-009 英文安装入口落到中文首页

- **现象**：中英文 14 个页面共用中文 manifest，用户从英文页安装后默认仍进入 `/`。
- **根因**：单一 manifest 同时承担两种语言入口，页面语言与 `start_url`、`lang` 没有映射合同。
- **解决**：保留中文 `manifest.webmanifest`，新增 `manifest.en.webmanifest`；英文 7 页改用 `/en/` 启动入口和 `en` 语言，根 scope 继续覆盖双语导航。
- **防复发**：验证器要求每页 `<head>` 恰有一个语言匹配的 manifest 链接，分别校验两份文件的入口、scope、语言和 ICO 元数据；真实安装行为继续使用浏览器验收。

### H-010 异常统计值被误判为有效计数

- **现象**：负数、小数或任意第三方文本可能被直接展示；无效主来源还可能遮蔽有效备用来源。
- **根因**：旧实现通过占位符黑名单判断有效性，并让计数与日期共用同一写入校验，缺少异常值和回退路径的运行测试。
- **解决**：计数改为只接受包含 `0` 在内的非负 ASCII 十进制整数字符串；逐来源选择首个有效值，全部无效时显示 `--` 且状态为 `warn`；日期文本使用独立写入路径。
- **防复发**：验证器固定统计脚本合同，运行测试覆盖 `0`、前导零、全角数字等异常格式、超长数字原样保留、备用源回退、全无效降级和日期保留。

### H-011 结构化数据混淆页面与人物实体

- **现象**：十个可索引页面曾直接使用 `Person` 根对象，只有两页声明页面语言，404 的 JSON-LD 排除也未自动验证。
- **根因**：页面与人物身份混合；旧验证器只检查块存在、JSON 可解析和可选语言值。
- **解决**：12 页改为页面专属统一 `@graph` 与稳定 ID，项目/研究使用详细公开实体，统计页遵守隐私边界，并由严格只读验证器检查。
- **防复发**：变异测试覆盖位置、类型、ID、引用、跨页一致性、可见证据和隐私边界；Chrome 对 12 个可索引路由全量检查。

### H-012 Lightbox 清理破坏抽屉既有 `inert`

- **现象**：移动抽屉关闭时本应保持 `inert`，但打开再关闭 Lightbox 后，屏外抽屉链接重新进入键盘 Tab 顺序。
- **根因**：`setElementInert` 只记录原有 `aria-hidden`，清理时无条件移除 `inert` 属性并把属性值设为 `false`，没有区分既有状态与本次模态新增状态。
- **解决**：首次模态激活时同时快照元素是否已有 `inert` 属性或属性值；清理时保留原有 `aria-hidden` 恢复路径，并同步恢复快照中的 `inert` 属性与属性值。
- **防复发**：自动合同集中维护于[共享交互结构合同](testing.md#38-共享交互结构合同)，统一验证 Lightbox 接线、处理器唯一性与覆盖、逐元素状态恢复；人工验收继续覆盖关闭抽屉的 Tab 顺序。本节只记录历史根因与解决方式。

## 4. 维护工作流

1. 先从当前代码和页面复现事实，不以旧文档作为结论。
2. 明确问题属于产品选择、代码缺陷、文档漂移还是已接受例外。
3. 需要用户选择或会修改个人内容时，实施前获得明确确认。
4. 每次只处理一个可验证边界，同步代码、文档和测试。
5. 按[测试规范](testing.md)运行自动与人工检查。
6. 完成后把维护队列条目移入“已解决的典型问题”，保留根因和防复发规则，删除过程流水账。

## 5. 新条目模板

```markdown
### M-NNN 简短标题

- **状态**：待决策 / 待修复 / 已接受。
- **事实**：用文件、选择器、状态或可重复现象描述当前行为。
- **风险**：说明会影响谁以及怎样失败。
- **修复边界**：列出需要同步的代码、文档和验证，不预写未经确认的方案。
```

## 6. 文档治理

- 当前合同写入架构、设计、测试或运维的唯一事实源，不在本文复制正文。
- 本文只保留仍需行动的偏差和具有复用价值的根因。
- Git 提交历史承担版本追踪；本文不维护日期式 changelog。
- 已失效、无防回归价值的过程记录直接删除，不另建 archive。
- 任何公开材料都需要通过人工隐私审查；自动验证不能替代内容授权。
