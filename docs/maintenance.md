# 维护记录

本文集中记录当前实现偏差、后续修复队列以及值得保留的事故经验。它不是测试说明、运维手册、版本流水账或愿望清单；执行命令分别见[测试规范](testing.md)和[运维指南](operations.md)，系统合同见[架构文档](architecture.md)。

## 1. 状态规则

| 状态 | 含义 |
| --- | --- |
| 待决策 | 事实已确认，但产品期望或修复边界尚未确认 |
| 待修复 | 期望明确，可以进入单独实现任务 |
| 已接受 | 当前行为是有意例外，文档已如实说明 |
| 已解决 | 代码或文档已修复，并有回归检查 |

任何条目只有在代码、文档和验证证据同步后才能标为“已解决”。测试未覆盖的行为必须注明人工检查边界。

## 2. 当前维护队列

### M-003 档案页双语结构不完全对称

- **状态**：已接受，等待未来内容任务重新评估。
- **事实**：中文档案使用独立 `#gap-year` 阶段，英文把相同经历放在研究生阶段；两种语言的项目卡片数量也不同。中文页另有两处内联 `style`。
- **风险**：不能用逐节点对比判断双语一致；“禁止任何内联样式”也不是当前已满足的合同。
- **回归边界**：维护语义、链接和证明材料一致性，同时把结构差异当作显式例外。

### M-007 CSS 媒体查询分散

- **状态**：已接受，等待样式重构任务。
- **事实**：1068/1069、833、640、419 等断点分布于样式表多个位置，顺序并非严格从大到小。
- **风险**：后续规则容易被文件尾的同断点覆盖；仅阅读某一段不能得到完整级联。
- **回归边界**：文档记录真实断点，修改响应式规则时检查全部同断点块；不要在文档中假称已经集中。

## 3. 已解决的典型问题

### H-001 品牌标识事实漂移

- **现象**：部分旧文档把品牌标识描述为 Font Awesome terminal，实际代码已使用 PNG 背景图。
- **根因**：视觉实现更新后，多份重复文档没有同步。
- **解决**：设计与架构只保留 PNG 合同，删除重复术语文档。
- **防复发**：以 CSS 和实际资源为事实源；品牌合同只在[设计规范](design.md)展开。

### H-002 404 被误当作普通 SEO 页面

- **现象**：旧说明一度把 canonical、hreflang 和结构化数据描述成“每页必需”，同时又把 404 `noindex` 误列为未完成债务。
- **根因**：没有把 12 个可索引页面与 2 个错误页面分成两套合同。
- **解决**：404 当前是 `noindex`、无 canonical/hreflang/JSON-LD 且不进 sitemap。验证器自动检查 `noindex`、canonical、hreflang、活动 JSON-LD 和 sitemap 排除。
- **防复发**：测试矩阵始终分开描述普通页面和 404。

### H-003 统计范围被写成全站

- **现象**：旧文档把本地累计访问描述成覆盖全部页面。
- **根因**：忽略了 `stats.js` 实际只在中英文首页与统计页加载。
- **解决**：架构与设计明确四页范围，验证器核对脚本加载清单和 DOM。
- **防复发**：新增统计页面时同步更新页面清单、脚本、测试和文档。

### H-004 Sitemap 日期语义被误判

- **现象**：旧运维说明把多个 URL 的相同 `lastmod` 日期视为错误。
- **根因**：混淆了内容历史日期与生成器读取的本地 HTML mtime。
- **解决**：合同改为“每条由对应 HTML mtime 生成，允许同日”。
- **防复发**：验证日期格式和页面集合，不凭日期是否相同判断正确性。

### H-005 双语证明图同步债务过期

- **现象**：部分旧文档仍把英文证明图缺失列为当前债务。
- **根因**：修复完成后，债务段落没有转为历史记录。
- **解决**：当前中英文证明图库存已同步，过期债务从当前架构移除。
- **防复发**：资源变更时按中英文路径和顺序做成对检查；完成项迁入本节，不继续占用维护队列。

### H-006 移动抽屉跨断点状态残留

- **现象**：在移动断点打开抽屉后切入桌面状态，`menu-open`、背景 `inert`、遮罩、滚动锁和抽屉焦点曾继续残留；首次整数边界修复后，页面缩放形成 `833px < width < 834px` 的小数 CSS 视口时仍可复现。
- **根因**：初始实现没有监听断点变化；首次修复又让 JavaScript 使用 `(min-width: 834px)`，而 CSS 的事实源是 `(max-width: 833px)`。两者在整数宽度上相邻，但在小数 CSS 像素中留下两个查询都不匹配的间隙。
- **解决**：JavaScript 改为共享 CSS 的 `(max-width: 833px)` 移动谓词，并在查询从匹配变为不匹配时复用关闭逻辑；继续保留不聚焦隐藏菜单按钮、抽屉内焦点转移、无当前项时的首个桌面链接回退，以及待执行动画帧的状态保护。
- **防复发**：验证器用平衡块与顶层声明解析要求目标 CSS 媒体块位于整份样式表顶层，并在同一媒体块的顶层包含精确直接导航规则，再核对全部合格同谓词块合并后的有效 `display` 值；同时把精确谓词、变量、监听器、顶层 `event.matches` 退出门及其先于清理的顺序作为同一结构合同。变异测试拒绝 CSS 漂移或拆块、外层或内层嵌套条件组、同规则/后续规则/后续媒体块覆盖、普通或嵌套自定义属性伪装、旧 `min-width` 实现、嵌套退出门以及注释/字符串伪实现，浏览器验收同时核对 833px、小数间隙和 834px 的类名、`inert`、遮罩、滚动与焦点。

### H-007 Manifest 图标尺寸元数据漂移

- **现象**：`site.ico` 实际包含 16、32、48、256 像素图层，manifest 却漏报三层并虚报 64、128 像素。
- **根因**：图标资源替换后只同步了路径，没有同步尺寸元数据，也没有实物解析验证。
- **解决**：manifest `sizes` 改为 `16x16 32x32 48x48 256x256`；验证器解析 ICO 目录并精确比较声明集合，畸形或截断文件会安全报错。
- **防复发**：图标替换时同时同步两份 manifest，并运行尺寸不匹配与 ICO 截断回归用例，不再把“路径存在”当成元数据正确。

### H-008 非统计页遗留统计服务连接提示

- **现象**：英文项目页不加载 `stats.js` 或公开计数资源，却保留了旧外部计数源的 preconnect。
- **根因**：页面从统计模板派生后删除了脚本，但没有同步删除连接提示，也缺少依赖范围验证。
- **解决**：删除无用途连接提示；当前只有四个统计页面可以预连接自管 Worker，其他页面不得出现 endpoint、preconnect 或统计脚本。
- **防复发**：页面增删统计能力时同时核对脚本、计数 DOM、endpoint 与连接提示，非统计页回归用例会阻止依赖范围再次扩大。

### H-009 英文安装入口落到中文首页

- **现象**：中英文 14 个页面共用中文 manifest，用户从英文页安装后默认仍进入 `/`。
- **根因**：单一 manifest 同时承担两种语言入口，页面语言与 `start_url`、`lang` 没有映射合同。
- **解决**：保留中文 `manifest.webmanifest`，新增 `manifest.en.webmanifest`；英文 7 页改用 `/en/` 启动入口和 `en` 语言，根 scope 继续覆盖双语导航。
- **防复发**：验证器要求每页 `<head>` 恰有一个语言匹配的 manifest 链接，分别校验两份文件的入口、scope、语言和安装 PNG 清单；HTML favicon 作为独立固定资产校验，真实安装行为继续使用浏览器验收。

### H-010 异常统计值被误判为有效计数

- **现象**：负数、小数或任意响应文本可能被直接展示，公开值之间也可能来自不一致的响应阶段。
- **根因**：旧实现逐个读取异步注入的隐藏节点，通过占位符黑名单判断有效性，并让计数与日期共用同一写入校验。
- **解决**：客户端只接受一个完整 Worker JSON：三个计数均为包含 `0` 在内的非负 ASCII 十进制字符串，年月和起始日期同时匹配；任一字段无效时三项统一显示 `--` 且状态为 `warn`，日期文本继续使用独立写入路径。
- **防复发**：验证器和独立客户端测试覆盖合法零值、超长数字、字段缺失、全角数字、错误年月/起始日期、网络错误与统一降级。

### H-011 结构化数据混淆页面与人物实体

- **现象**：十个可索引页面曾直接使用 `Person` 根对象，只有两页声明页面语言，404 的 JSON-LD 排除也未自动验证。
- **根因**：页面与人物身份混合；旧验证器只检查块存在、JSON 可解析和可选语言值。
- **解决**：12 页改为页面专属统一 `@graph` 与稳定 ID，项目/研究使用详细公开实体，统计页遵守隐私边界，并由严格只读验证器检查。
- **防复发**：变异测试覆盖位置、类型、ID、引用、跨页一致性、可见证据和隐私边界；Chrome 对 12 个可索引路由全量检查。

### H-012 Lightbox 清理破坏抽屉既有 `inert`

- **现象**：移动抽屉关闭时本应保持 `inert`，但打开再关闭 Lightbox 后，屏外抽屉链接重新进入键盘 Tab 顺序。
- **根因**：`setElementInert` 只记录原有 `aria-hidden`，清理时无条件移除 `inert` 属性并把属性值设为 `false`，没有区分既有状态与本次模态新增状态。
- **解决**：首次模态激活时同时快照元素是否已有 `inert` 属性或属性值；清理时保留原有 `aria-hidden` 恢复路径，并同步恢复快照中的 `inert` 属性与属性值。
- **防复发**：自动合同集中维护于[共享交互结构合同](testing.md#38-共享交互结构合同)，统一验证 Lightbox 接线、处理器唯一性与覆盖、逐元素状态恢复；人工验收继续覆盖关闭抽屉的 Tab 顺序。本节只记录历史根因与解决方式。

### H-013 简历材料网格在窄屏撑大页面

- **现象**：中英文简历页在 `640px` 时出现 82px 页面横向溢出，在 `420px` 和 `375px` 分别扩大到 302px 与 322px；`320px` 极窄屏还会裁切联系方式长值和英文长按钮。
- **根因**：单列 `.doc-grid` 的 `.doc-card` 保留自动最小尺寸，内部可横向滚动的 `.proof-grid` 参与最小内容宽度计算并反向撑大网格；侧栏 flex 行与不换行小按钮也没有显式收缩边界。
- **解决**：文档卡片和联系方式行显式使用 `min-width: 0`，联系方式值增加任意位置换行；简历主体长小按钮限制为父容器宽度并恢复正常换行。证明图继续只在自身滑轨滚动。
- **防复发**：验证器要求四组精确选择器以全局顶层规则提供收缩属性，并以 `#main-content` 下当前实际元素（含长动作的 `.subtle` 变体）作为重叠目标；组合符空白和选择器列表先规范化，再按源码顺序、选择器特异性（含 `:nth-child(... of selector)`）与 `!important` 判断实际层叠。注释、字符串、错误值、较短的强制覆盖、更高特异性覆盖及条件覆盖均会被拒绝，较低优先级基础样式、无关属性、最终 subject 的类型/ID/类单 compound `:not(...)` 排除和伪元素规则不误报；祖先否定、属性/通配符否定或带组合符、嵌套函数、状态的复杂函数选择器若可能覆盖保护值则保守拒绝。高优先级错误候选逐条禁止，后续安全声明不豁免陈旧规则。浏览器矩阵同时测中英文 1440–320px，并阻断 PDF 与非本地请求。

### H-014 英文深层缺失路径显示中文且资源失效

- **现象**：GitHub Pages 在 `/en/...` 缺失路径返回根 `404.html`，而根页只有中文并固定跳 `/`；其相对 CSS、脚本和导航还会按缺失 URL 的目录解析，深层路径出现资源 404 与错误链接。物理 `en/404.html` 不会被 Pages 自动选作英文 fallback。
- **根因**：旧实现把两个物理 404 当成按目录自动分派的页面，并各自维护内联倒计时；验证器只按文件在磁盘中的目录解析引用，没有模拟缺失 URL 的路径基准、语言边界或计时行为。
- **解决**：保留两个物理文件，根 404 改为单一 DOM 的成对双语映射和根绝对本地路径；`site.js` 在其他交互前按精确 `/en` 边界原地应用现有英文内容，并统一两页 5 秒倒计时。倒计时结束前不改变 URL，缺失主文档继续由 Pages 返回 HTTP 404。
- **防复发**：验证器拒绝相对根页路径、映射缺口或实体英文页诱饵映射、根页英文语义与物理英文实际值漂移、普通页面地址副作用、倒计时前地址对象写入、可执行内联脚本、宽泛语言前缀、错误初始化顺序、错误目标或时长；浏览器矩阵用自定义 Pages-like handler 验证深层中英文与反例路径、英文内容等价、375/833/834/1440px 导航、资源响应、URL/404 保留及两种真实倒计时。详细合同分别由[架构文档](architecture.md#88-两个-404-页面)和[测试规范](testing.md#77-404)维护。

### H-015 Manifest 安装图标与 favicon 职责混用

- **现象**：两份 manifest 曾把多尺寸 `site.ico` 作为唯一 icon，缺少面向安装入口的 192×192 与 512×512 PNG，并让 favicon 元数据同时承担安装图标合同。
- **根因**：旧实现复用了 HTML favicon，验证器也只从 manifest 读取 ICO 并比较图层，未把安装 PNG 与固定 favicon 分成两个资产边界。
- **解决**：从现有方形品牌图用 Lanczos 机械生成两张安装 PNG；两份 manifest 只保留这两项并声明 `purpose: any`，不宣称 maskable。`site.ico` 继续保留 16、32、48、256 像素图层，仅承担 HTML favicon。
- **防复发**：验证器按 `src` 无序精确比较两份安装清单，并分别检查安装 PNG 与独立 favicon 的签名、IHDR、块/entry 边界和尺寸关系；PNG CRC 与像素完整解码不在自动验证范围，视觉质量及浏览器真实安装行为仍按[测试规范](testing.md#5-自动验证明确不覆盖的事项)人工验收。

### H-016 本地统计键改名后旧记录静默重置

- **现象**：旧版页面已经保存的本机累计次数、首次访问和访问日期，在共享统计脚本上线后看起来从零开始；旧数据仍留在浏览器中，但新脚本不再读取。
- **根因**：统计逻辑从页面内联脚本抽到共享文件时，把四个下划线键静默改成连字符键，没有迁移层；验证器只用规范键构造单一日期场景，既未覆盖旧键，也不能观察存储结果。
- **解决**：在本次访问更新前按字段迁移通过历史形状校验的累计次数、首次访问和访问日期；只有严格缺失的规范键可接收旧值，现有规范数据始终优先，两套历史不相加，损坏字段不激活且不阻断合法兄弟字段。最近访问由本次加载直接建立，不执行立即被覆盖的旧值复制；全部旧键继续保留，后来新增的页面计数没有伪造映射。精确键、值形状和非合并政策由[架构文档](architecture.md#6-访问统计)维护。
- **防复发**：验证器在隔离 VM 中核对页面值、最终存储和完整写入/删除轨迹；变异测试分别删除旧字段、瞬时覆盖规范字段、瞬时迁入伪造页面计数和注入损坏旧值，测试入口及人工场景由[测试规范](testing.md#34-统计范围)维护。

### H-017 本地规范计数因数值转换损坏或失真

- **现象**：规范累计或页面计数为空、损坏或使用非整数格式时可能被写成 `NaN`；超过 JavaScript 安全整数后还会丢失精度、停止递增或转成科学计数法。
- **根因**：旧实现使用 `parseInt` 和 `Number` 加法，既没有严格验证规范值形状，也把持久化计数绑定到 IEEE-754 安全整数范围。
- **解决**：累计与页面计数只接受无前导零的非负 ASCII 十进制串，通过逐位字符串运算精确加一；缺失或损坏值在当前访问恢复为 `1`，有效值不设安全整数或长度上限。
- **防复发**：验证器同时核对存储与页面值，覆盖 `0`、普通值、安全整数边界两侧、任意长度进位及各类损坏输入；变异测试拒绝 `Number`、`parseInt`、`BigInt` 和宽松前导零实现，人工场景由[测试规范](testing.md#76-统计)维护。

### H-018 损坏的规范访问日期历史未被归一化

- **现象**：已有但非规范的首次访问时间会被继续展示；访问日期数组中的混合类型、无效日历日期和重复项会长期保留，今天可能不在末尾，超过 365 项的数据也可能绕过截断。
- **根因**：旧逻辑只在首次访问值为假时重建时间，并且仅在今天尚未出现时追加、保存日期；它没有严格验证 ISO 往返、日期数组形状与真实日历日期，也没有在每次加载时统一去重、统一今天的位置和执行长度上限。
- **解决**：每次加载只保留可与 `toISOString()` 完全往返的首次访问值，否则用同一当前时间快照重建首次与最近访问；日期数组只保留真实 `YYYY-MM-DD` 字符串，按原顺序稳定去重，唯一追加今天后截取最后 365 项并持久化。损坏的现有规范值仍不回退到历史键，存储结果与页面显示保持一致。精确合同由[架构文档](architecture.md#6-访问统计)维护。
- **防复发**：验证器用逐次前进的受控时钟核对单次时间采样、规范与损坏时间、合法历史键诱饵、混合/重复/超长日期数组及最终页面文本；正向与变异测试和人工矩阵由[测试规范](testing.md#34-统计范围)维护。

### H-019 公开统计失败提示迟缓且状态不可播报

- **现象**：旧公开统计请求被阻断时，四个统计页面会长时间保持“正在获取”；加载节点最初也没有实时状态区语义。
- **根因**：旧实现依赖重复轮询多个异步隐藏节点，把全部等待预算耗尽后才判定失败，也没有把异步变化建模为可访问状态机。
- **解决**：改为单次 Worker JSON POST 和 5 秒中止期限；成功只进入 `ok`，任一失败统一进入 `warn`。四页状态节点保留礼貌、原子更新的 `role="status"` 实时区。
- **防复发**：验证器与客户端测试同时检查四页初始标记、单次请求、期限、定时器清理、完整响应和失败轨迹；变异测试拒绝延长期限、错误方法/path、部分展示或移除实时区属性。

### H-020 导航品牌图按设计母版原尺寸传输

- **现象**：全站以 16×16 显示的品牌图实际为 1024×1024、458,419 字节；冷缓存访问会为这个微型标识额外传输约 448 KiB。
- **根因**：设计母版直接兼任运行时导航资源，没有为真实显示尺寸建立像素密度和体积边界。
- **解决**：使用 Lanczos 将导航资源机械缩放为 64×64 PNG，输出为 3,198 字节，在四倍像素密度下保留原视觉；安装图标继续使用独立的 192×192 与 512×512 文件，个人图片和证明材料不变。
- **防复发**：验证器固定检查品牌 PNG 的结构、64×64 IHDR 和 16 KiB 上限；变异测试分别拒绝尺寸漂移与体积膨胀。

### H-021 档案证明卡片尺寸分叉且仅依赖滚动条

- **现象**：档案页的普通、宽版和紧凑证明滑轨分别使用 280px、320px 和 240px 卡片，说明文字多少还会改变卡片高度；桌面用户除底部原生滚动条外没有直接拖动入口。英文极窄屏的长阶段标签还会把整页额外撑宽约 11px。
- **根因**：三个展示变体分别覆盖卡片宽度，卡片没有统一高度；共享交互只处理 Lightbox，没有区分鼠标点击与滑轨拖动。档案邮箱和阶段摘要标签也沿用了不可收缩的通用标签语义。
- **解决**：所有证明卡片统一为响应式 280px 上限和 366px 固定高度，图片保持 4:3、说明区填充剩余空间；桌面鼠标超过 6px 阈值后进入抓取拖动，并隔离拖动产生的点击，触屏、普通点击、键盘和原生滚动条继续可用。中英文档案只公开两组批准邮箱，移除电话与微信；邮箱和阶段摘要标签增加窄屏换行保护。
- **防复发**：验证器精确核对双语联系方式、标签收缩、统一卡片尺寸与无变体覆盖，并在受限 VM 中执行拖动处理器验证阈值、方向、捕获、清理和点击隔离；浏览器验收继续检查实际尺寸、页面横向溢出、鼠标拖动、普通点击、键盘与触屏边界。

### H-022 首页移动概要卡片拥挤且层级分散

- **现象**：移动端首页右侧卡片受 `min(86vw, 340px)` 上限约束，当前卡片偏窄而相邻卡片仍大面积露出；身份、关键词与统计采用不同高度和多层胶囊/小卡框，配合密集背景网格显得拥挤。320px 下长英文关键词、统计标签及 8 位访问量还可能越出各自单元格。
- **根因**：移动 Hero 沿用多套桌面组件的独立最小内容和高度，没有建立滑轨级统一尺寸；关键词与统计继续把每个条目当作独立卡片，计数沿用桌面字号，静态验证器也没有覆盖这组移动视觉合同。
- **解决**：保留原有横向浏览方式并改为居中吸附的档案式滑轨，卡片使用容器减 `56px` 的宽度、`28px` 两端留白与 `216px` 统一高度，使首卡居中时稳定露出下一卡 `16px`；身份联系方式改为信息行，关键词合并为 2×3 矩阵，统计合并为三栏分段面板，并降低背景网格密度。英文标签和关键词允许换行，公开计数在窄屏使用自适应等宽字号并限制在分栏内。
- **防复发**：验证器检查 `<= 640px` 的最终有效卡宽、卡高、吸附、内部组合、文字换行、计数字号与背景网格，10 个名称子集用例拒绝旧上限、尺寸分叉和各类嵌套/溢出回归；浏览器验收覆盖中英文 320/375/419/640px、8 位计数、触摸吸附与双主题。

### H-023 公开独立访客长期为零且口径不可控

- **现象**：页面访问能够出现，公开独立访客却长期为 `0`；多个外部脚本的可用性、更新时机与指标定义无法由项目验证。
- **根因**：静态页面没有自管写入接口或数据表，同一页面同时依赖不同外部计数机制，客户端只能轮询注入结果，无法建立稳定的月界、隐私、失败与基线合同。
- **解决**：完全移除旧运行时，新增 Cloudflare Worker + D1。公开统计于 `2026-07-22` 从零开始，不导入旧值；站点/页面次数按成功请求累计，“本月独立设备（估算）”按上海时区自然月对 IP 与 User-Agent 的 HMAC 摘要去重。原始 IP、User-Agent 和首次出现时间不落库，最终月度表只含月份与摘要；跨月首个有效访问清理旧摘要。
- **防复发**：四页固定唯一 endpoint 与 preconnect，验证器拒绝旧运行时和依赖范围扩大；客户端、Worker、真实 migration、健康端点与浏览器矩阵分别覆盖响应、CORS、月界、D1 失败和隐私结构。发布前测试计数必须归零并只读确认。

### H-024 首页引文区占用过高的章节权重

- **现象**：桌面首页的一句引文被 `42vh` 最小高度扩展到 420px，接近研究与项目概览整段的高度；在不同屏高下，留白还会随视口而变化。
- **根因**：装饰性引文使用视口比例决定高度，而不是服从全站 `.section-block` 的内容和响应式留白体系。
- **解决**：移除引文区的视口最小高度，保留原有引文、背景、居中方式与全站区块内边距；中文页实测在 1440×1000 下由 420px 收敛为 305px，在 320×900 下由内容自然撑开为 342px。英文引文因文本更长而保留自己的自然高度。
- **防复发**：当前合同见[设计规范](design.md#32-hero)，桌面与移动验收见[测试规范](testing.md#7-浏览器验收矩阵)；双语页面继续核对上下留白、可读性、页脚衔接和页面横向溢出，不要求自然高度相同。

### H-025 首页相邻深色章节合并为大面积黑块

- **现象**：引文区高度收敛后，研究与工程概览仍与引文连续使用相同深色背景；两段各自的上下留白在视觉上合并，浅色主题下形成约 767px 的连续黑色区域。
- **根因**：概览导航与情绪收尾承担不同信息职责，却同时使用章节级 `.tile-dark`，设计文档此前只约束单个引文高度，没有约束相邻章节的明暗节奏。
- **解决**：中英文首页概览改用 `.section-block.section-muted`，保留现有白色卡片、内容、按钮和响应式布局；引文继续作为唯一的深色收尾锚点。1440×1000 浅色主题下形成白色 Hero、`#ececee` 浅灰概览与 `#272729` 深色引文，不再合并成连续黑块，也避免 Hero 与概览连成大面积纯白。
- **防复发**：相邻主区块不连续使用 `.tile-dark`，首页概览不得移除 `.section-muted` 或把内部卡片改成同色背景；当前语义见[设计规范](design.md#33-表面与卡片)，中英文首页在双主题和关键断点按[测试规范](testing.md#7-浏览器验收矩阵)核对完整的 Hero、概览、引文与页脚节奏。

### H-026 全站章节底色随 DOM 顺序漂移

- **现象**：项目、简历和统计页看似按灰白交替，实际由直属 `section` 的奇偶位置决定；研究页又在中间插入深色章节。不同页面因此形成互不一致的灰、白、黑色序，增删一个章节还会反转后续全部底色。
- **根因**：共享 CSS 使用 `.section-block:nth-of-type(2n+1)` 推导章节色调，而 `:nth-of-type` 会连同 `.page-hero` 等其他直属 `section` 一起计数；该位置规则与 `.section-muted`、`.tile-dark` 两套语义类同时存在。
- **解决**：移除 DOM 奇偶选择器，普通章节保持基础画布，需要分章的研究、项目、简历和统计章节在中英文页面显式使用 `.section-muted`；研究核心问题由深色改为中性灰，正文深色章节只保留首页引文。内页统一形成浅灰 Hero 后的白灰节奏。
- **防复发**：章节增删不得依赖位置自动换色；双语页面按[设计规范](design.md#33-表面与卡片)同步语义类，并按[测试规范](testing.md#7-浏览器验收矩阵)核对浅深主题下的完整色序。

### H-027 内页 Hero 被视口比例拉出多余留白

- **现象**：普通内页统一使用 `52vh` 最小高度。`1440×1000` 下十个中英文内页 Hero 因此全部至少为 `520px`，但档案、简历和统计页的内容加上下内边距只需要约 `304–457px`；高屏下空白还会继续放大。
- **根因**：单一、无上限的视口比例同时承担页面气势和内容容纳两种职责，没有区分简单标题页与带多行说明、按钮的长英文页面。
- **解决**：共享 `.page-hero` 显式改为 `min-height:auto`，保留原有居中、网格背景和响应式内边距，让每页按实际内容自然生长。`1440×1000` 下中文档案与统计页由 `520px` 分别收敛到 `304px` 和 `329px`，英文研究页按内容保持 `507px`；`1440×1400` 下也不再统一膨胀到 `728px`。
- **防复发**：不得给 `.page-hero` 增加固定高度、额外高度下限、内容裁切或视口比例最小高度；按[设计规范](design.md#32-hero)和[测试规范](testing.md#7-浏览器验收矩阵)同时覆盖简单页、长英文页、短高视口、超高视口与移动断点。

## 4. 维护工作流

1. 先从当前代码和页面复现事实，不以旧文档作为结论。
2. 明确问题属于产品选择、代码缺陷、文档漂移还是已接受例外。
3. 需要用户选择或会修改个人内容时，实施前获得明确确认。
4. 每次只处理一个可验证边界，同步代码、文档和测试。
5. 按[测试规范](testing.md)运行自动与人工检查。
6. 完成后把维护队列条目移入“已解决的典型问题”，保留根因和防复发规则，删除过程流水账。

## 5. 新条目模板

```markdown
### M-NNN 简短标题

- **状态**：待决策 / 待修复 / 已接受。
- **事实**：用文件、选择器、状态或可重复现象描述当前行为。
- **风险**：说明会影响谁以及怎样失败。
- **修复边界**：列出需要同步的代码、文档和验证，不预写未经确认的方案。
```
